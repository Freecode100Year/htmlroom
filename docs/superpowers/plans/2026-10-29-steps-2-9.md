# HTML Room 第 2–9 步实施计划

用户授权：继续完成任务清单第 2–9 步，每步独立 PR，测试完成后合并。

## 全局约束

文件脚本/样式使用精确 SHA-256 CSP，中继仅精确来源（回环开发例外沿用）。无新增第三方运行时依赖、遥测或 CDN。秘密不进日志/查询参数；access/resume 仍仅用于现有必要的中继鉴权。变更客户端后同步 dist 与 release-integrity.json。协议/安全影响用中文记录，破坏兼容时在 PR 明说。真机、ECH 和账户内验证不得编造成已完成。

## 执行顺序

1. **任务 2**：Cloudflare 按钮、缺少 JOIN_LIMIT 时一次无敏感信息警告、全新构建验证、官方来源 ECH 文档。
2. **任务 3**：POSIX 安装脚本，DNS 前检、幂等/卸载、GHCR 默认镜像/源码构建，tag 多架构镜像和 shellcheck/容器 CI。
3. **任务 4**：核实密码原语，官方 KAT 和协议固定向量，来源/许可证、负面用例；发现生产不一致只记录。
4. **任务 5**：安全码核对提示、仅内存的已核对状态和成员标记、无障碍、浏览器测试。
5. **任务 6**：日志清查、限流键带盐哈希和清理、隐私文档、敏感日志回归测试。
6. **任务 7**：严格有界长度填充、控制帧长度与威胁边界、固定向量/边界测试、带宽评估。
7. **任务 8**：基于最终代码的双语审计材料与可复现说明，引用源码行号、明确差异，不改生产代码。
8. **任务 9**：真机矩阵和记录模板；移动视口/WebKit、无 JS/无 WebCrypto/无 WebSocket 自动化与 CI；仍标记未完成真机验证。

## 每步交付门槛

实现者独立提交，独立审查，修复实质问题；运行 `npm test`、`npm run build:check`、`npm run test:browser`、`npm run test:pages`、`npm run test:worker`、`npx wrangler deploy --dry-run`。PR 记录测试、破坏兼容和残留局限，GitHub CI 通过后合并。已授权持续执行，不再逐步询问。

## 冲突与边界

任务 4 先冻结当前协议；任务 7 若改变线格式须更新对应协议向量。任务 8 按其步骤时的实际代码标行号；任务 9 若影响引用位置，应维护审计索引。已有根目录 Bash 安装脚本须迁移或保留明确兼容入口，避免两套实现漂移。无 Cloudflare 账户权限、无物理设备时交付可执行验证步骤并明确未验证，不猜测结果。
